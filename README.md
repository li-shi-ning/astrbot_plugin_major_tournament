# astrbot_plugin_major_tournament

> AstrBot「Major 赛制」锦标赛插件：群内报名 → 管理员人工判胜 → 自动生成 **32/16/8/4/2 强** 单败淘汰赛程 → 渲染 Major 风格对阵图。

## ✨ 功能

- **房主机制**：第一个创建赛事（首次报名/命名）的人成为「房主」，房主与管理员可开赛、判胜、命名、重抽、重置；普通群友只能报名/查看。
- **报名不限人数**：默认报名阶段不设人数上限，开赛时再按实际报名人数自动确定规模（2/4/8/16/32/64 强）。支持自定义显示名、房主/管理员代报名。
- **人工判胜**：每一场由管理员手动指定胜者（支持按位置 `1`/`2` 或输入选手名字），并可选记录比分。
- **随机抽签**：`major 开赛` 时对报名选手**随机抽签**（不是报名顺序），抽签结果会回显在开赛消息里；开赛后还未产生真实结果前，管理员可用 `major 重抽` 重新抽签。
- **自动排赛**：`major 开赛` 不填规模时，自动取「不小于报名人数的最小 2 的幂」；也可手动指定 `32/16/8/4/2`。采用**标准种子排位**（`1vN`、`2v(N-1)` …），高种子不会提前相遇；人数不足时自动**轮空晋级**。
- **自动晋级**：判定一场胜负后，胜者自动进入下一轮；决赛判定后自动产生冠军。
- **对阵图渲染（带头像）**：参考 `astrbot_plugin_qq_group_daily_analysis` 的 T2I 方案；自动下载每位选手的 QQ 头像（官方机器人用 `appid + openid`，OneBot 用 QQ 号），缩放后以 base64 内嵌，T2I 无需访问外网。头像取不到时回退首字母圆形。
- **按钮面板（QQ 官方机器人）**：发送 `major` 即可收到 Markdown + 按钮面板，报名 / 退赛 / 名单 / 赛程 / 判胜全部可点击完成，无需记指令。
- **SQLite 数据库持久化**：赛程、每场比分与结果写入 `major.db`，可随时用「major 记录」查询；重置赛事后历史仍保留。

## 📦 安装

1. 把本仓库克隆/复制到 AstrBot 的 `data/plugins/` 目录下：

   ```bash
   cd AstrBot/data/plugins
   git clone https://github.com/li-shi-ning/astrbot_plugin_major_tournament.git
   ```

2. 重启 AstrBot 或在 WebUI 插件页重载插件。
3. 依赖：`jinja2>=3.1`（AstrBot 已内置；若缺失请 `pip install jinja2`）。

## 🧭 玩法流程

1. **创建房间**：房主发送 `major 创建房间 群友杯 8`（名称必填可选，规模 `8` 可省略）。
   - 在 QQ 官方机器人上直接点「🏠 创建房间」按钮，会预填 `major 创建房间 `，你再补上「名称 规模」即可。
   - 创建者自动成为**房主**。
2. **大家报名**：群友点「📝 报名」或发送 `major 报名`。
3. **开赛**：房主点「🚀 开赛」或发送 `major 开赛`；未指定规模时按实际报名人数自动初始化（2/4/8/16/32/64），并随机抽签。
4. **人工判胜**：房主/管理员点对阵按钮或 `major 胜 <编号> <1\|2\|名字> [比分]`，胜者自动晋级，直到决出冠军。

## 🎮 指令

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `major` / `major面板` | 所有人 | 发送按钮面板（QQ 官方）；其它平台发帮助 |
| `major 帮助` | 所有人 | 查看帮助 |
| `major 创建房间 [名称] [规模]` | 所有人 | 创建房间（创建者即房主）；规模可省略，开赛时按人数自动确定 |
| `major 报名 [名字]` | 所有人 | 报名参赛（需先有房间） |
| `major 退赛` | 所有人 | 取消报名（仅开赛前） |
| `major 名单` | 所有人 | 查看报名名单 |
| `major 开赛 [名称] [规模]` | 房主/管理员 | 开赛；不填则沿用创建房间时的名称/规模（规模缺省时按报名人数自动确定） |
| `major 对阵` | 所有人 | 文字版赛程 |
| `major 图` | 所有人 | 渲染 Major 对阵图 |
| `major 胜 <编号> <1\|2\|名字> [比分]` | 房主/管理员 | 判定胜负，例：`major 胜 R16-3 1 2:1` |
| `major 命名 <名称>` | 房主/管理员 | 自定义比赛名称（也可用 `major 开赛 4 我的杯` 顺带命名） |
| `major 重抽` | 房主/管理员 | 重新随机抽签（仅开赛后、未产生真实结果前） |
| `major 记录 [页码]` | 所有人 | 比赛记录列表（QQ 官方为按钮翻页，点按钮看详情） |
| `major 详情 <序号\|ID>` | 所有人 | 查看某场赛事的参赛人员 / 冠军 / 赛程 |
| `major 添加 <账号> [名字]` | 房主/管理员 | 代他人报名，支持 `@某人` |
| `major 重置` | 房主/管理员 | 删除当前赛事 |

别名：`锦标赛`、`major赛`、`major比赛`。  
比赛编号形如 `R32-1`（32 强第 1 场）、`R16-3`、`R2-1`（决赛）。

## 🔘 按钮面板（QQ 官方机器人）

在 QQ 官方机器人 / Webhook 平台发送 `major`（或不带参数的 `major面板` / `major按钮` / `major菜单`）会回复一条 **Markdown + 键盘按钮** 消息：

| 按钮 | 说明 |
| --- | --- |
| 📝 报名 / 🚪 退赛 | 所有人可见，开赛前可点击 |
| 🎲 重抽 | 开赛后、未产生结果前，管理员可重新随机抽签 |
| 👥 名单 / 📋 赛程 / 🖼 对阵图 | 查看类按钮 |
| 🏠 创建房间 | 还没有房间时显示；输入框按钮，点击后把 `major 创建房间 ` 填入输入框，可继续补「名称 规模」 |
| 🚀 开赛 | 创建房间后**始终显示**，方便房主随时开赛（点击时校验房主/管理员权限） |
| ⚔ 判胜 | 比赛进行中，房主/管理员面板**只显示「下一场」的两个按钮**（点谁谁晋级，面板自动刷新到再下一场），避免按钮数量触达平台上限 |
| 🗑 重置 | 仅房主/管理员面板显示 |
| ⚔ `<编号> <选手>` | 开赛后，管理员面板会为待判定的比赛各生成两个按钮，点谁谁晋级 |

实现要点（参考 `astrbot_plugin_util_official`）：

- 全部使用 `action.type = 2` 的**指令按钮**，点击后 QQ 会把按钮的 `data` 当作一条 @机器人 消息发出，因此 `data` 直接复用现有命令（如 `major 报名`、`major 胜 R16-1 1`），**不需要** `INTERACTION_CREATE` 回调，也不用补 interaction intent。
- 发送时附带被动回复上下文（`msg_id` + `msg_seq`），避免被平台当作主动消息拦截。
- 按钮通过 `event.bot.api.post_group_message(..., msg_type=2, markdown=..., keyboard=...)` 直接发送；发送成功后 `stop_event()`。
- 管理员按钮只是「面板可见性」层面的收敛，真正的权限校验仍在命令处理里（`event.is_admin()`），非管理员即使点到也会被拒绝。
- 相关配置：`buttons_enabled`（总开关，默认开）、`button_auto_refresh`（报名/退赛/开赛/判胜/重置后自动重发面板，默认开）。

## 📜 比赛记录（按钮列表 + 详情页）

在 QQ 官方机器人上发送 `major 记录`（或点「📜 记录」按钮），会得到一页 **按钮列表**：

```
📜 比赛记录（第 1/2 页 · 共 7 场）
1. 第7届杯 · 已结束 · 4人 · 冠军 选手7-3
2. 第6届杯 · 已结束 · 4人 · 冠军 选手6-3
…

[ 第7届杯 ]
[ 第6届杯 ]
[ 第5届杯 ]
[ 第4届杯 ]
[      ⬅ 上一页    |    ➡ 下一页      ]
```
> QQ 键盘最多 5 行，所以记录列表为 **4 行赛事 + 1 行分页**（每页 4 场，一行一个赛事，名称更完整）。

点某个赛事名称按钮进入**详情页**：

```
🏆 第7届杯
状态：已结束
创建：2026-09-16 13:20
参赛人员（4）：选手7-1、选手7-2、选手7-3、选手7-4
冠军：选手7-3

比赛赛程：
  [4强] R4-1 选手7-3 2:0 选手7-2  → 选手7-3
  [决赛] R2-1 选手7-3 2:0 选手7-1  → 选手7-3

[ 🖼 查看图像 ]   [ ⬅ 返回列表 ]
```

- 按钮直接显示**赛事名称**（一行一个；过长会截断，同页重名时自动加序号区分）。
- 分页：每页 4 场，`⬅ 上一页` / `➡ 下一页`。
- 详情页点「🖼 查看图像」会按该场赛事数据重新渲染（带头像的）对阵图。
- 非 QQ 官方平台自动回退为文字列表，可用 `major 详情 <序号>`（1 为最近一场）查看。
- 所有数据来自 SQLite（`major.db`），**重置赛事后历史仍保留**。

## 🖼️ 对阵图渲染说明

对阵图参考 **CS:GO Major 淘汰赛对阵树** 的视觉风格：

- 深绿径向渐变底 + 灰绿选手卡，胜者比分格为赛事绿
- 每列是「晋级到该轮」的选手，逐轮向右收敛，最后一列是冠军（金色）
- L 形连接线用内联 SVG 精确绘制
- 选手卡左侧是**圆形头像位**（取不到头像时回退首字母），中间是种子号 + 昵称（超长省略），右侧是该场比分
- 每列卡片垂直位置严格对齐上游两张卡的中点（标准淘汰树）

渲染链路：

0. `core/avatars.py` 下载选手头像并转成 data URI（官方机器人需要 appid + openid）；
1. `core/renderer.py` 计算每列卡片坐标与连接线，用 **Jinja2** 渲染完整 HTML（`templates/major_bracket.html`）；
2. 调用 AstrBot 的 `self.html_render(html, {}, return_url=False, options=...)`，由 T2I 服务把 HTML 转成图片字节；
3. 通过 `event.make_result().base64_image(...)` 发送，避免 OneBot / QQ 官方机器人访问不到内部地址。

> - **清晰度**：默认用 `device_scale_factor_level=ultra`（约 1.8x 像素密度），字和人像都更清晰；
>   大阵容按像素预算自动降档（ultra → high → normal），渲染失败也会自动降档重试。
> - **尺寸**：按内容设置视口，不留大片空白。实测 8 人约 1014×608（normal）/ 1825×1094（ultra），
>   16 人 1264×1072 / 32 人 1514×2000。
> - 可在插件配置里把 `image_scale` 设为 `normal` / `high` / `ultra`。
